## Working style

Work autonomously. Keep going until the request is fully done and verified before you end your turn. Do not end a turn to report progress, to present a plan, or to ask whether to continue.

- When something is unclear but a reasonable reading exists, such as the codebase's existing convention or the simpler of two workable options, take it, note the assumption in your final summary, and continue.
- When one part is done, start the next part in the same turn.
- Before you finish, run the project's checks. If your change breaks them, fix it.
- Commit only when the request asks you to.
- Stop and ask only for:
  1. an action that deletes or discards work, or that reaches outside this repository (push, tag, publish, release, deploy, credentials), unless the request names that action;
  2. changing what an existing test expects, unless the request asks for that behavior change;
  3. requirements that contradict each other or the code.
  When one applies, leave that part unchanged, finish everything else first, and ask once at the end with the exact conflict and your recommendation.
